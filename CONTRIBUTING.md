# Как ведётся этот проект

## Сборка и проверка

```bash
cargo build --release          # бинарь: target/release/gyrfalcon
cargo test --workspace         # 199 тестов
cargo fmt --all -- --check     # форматирование
cargo clippy --workspace --all-targets -- -D warnings
```

Все четыре шага — то же, что делает CI на Windows и Linux. Прогоняйте их
целиком перед пушем: правка исходника скриптом (`sed`, python) не проходит
через форматтер, и расхождение находит уже чужая машина.

Грамматики BSL и SDBL лежат в `crates/gyrfalcon-parser/vendor/` копией и
собираются своим `build.rs` — внешних зависимостей на сборку нет.

Приёмка гоняется отдельно, ей нужен собранный индекс:

```bash
cargo run --release -- build <путь к src> --out config.db
python tools/acceptance/run.py --our-only
```

## Дисциплина утверждений

Проект про инструмент, который отвечает агенту на вопросы о чужом коде. Цена
неверного ответа здесь выше обычной: агент не перепроверяет, он строит на ответе
следующий шаг. Отсюда правила, обязательные и для кода, и для документов.

**Цитата отдельно, вывод отдельно.** Цитата — взятое из источника дословно.
Вывод — полученное рассуждением, даже безупречным. Вывод помечается как вывод
и остаётся кандидатом на проверку.

**У замера есть дата.** Число без даты — мнение. Число, снятое полгода назад,
описывает прошлое состояние; при цитировании называется дата.

**Чужие цифры — чужие.** Заявки других проектов о скорости и полноте не переносятся
в наши выводы. Меряем сами, своим измерителем, на своём корпусе.

**Отсутствие не равно полноте.** Инструмент, ничего не нашедший, обязан сказать,
что искал и каким способом. Пустой ответ без объяснения читается как факт о мире —
и это худший режим отказа, потому что он не выглядит отказом.

## Заглушки

Нереализованная функция возвращает **ошибку**, а не пустой результат.
Пустой `Vec` от ненаписанного разбора неотличим от честного «в модуле нет методов»,
и разница вскроется через недели, на выводе, который уже куда-то попал.

## Код

- `cargo fmt` и `cargo clippy -D warnings` — до коммита; CI проверяет то же самое.
- Комментарии и документация — на русском: предметная область русскоязычная,
  и `ОбщийМодуль.ПриЗаписи` в англоязычном комментарии выглядит хуже, чем кажется.
- Имена в коде — латиницей, обычным для Rust образом.

## Замеры

Сырьё замера (логи, дампы) в репозиторий не едет — только сводка с датой,
корпусом, железом и версией измерителя. Воспроизводимость важнее краткости:
замер, который нельзя повторить, — анекдот.

## Что не попадает в репозиторий никогда

- исходники и выгрузки конфигураций 1С (чужой код, часто коммерческая тайна);
- собранные индексы и базы справки;
- токены, пути машины, имена проектов и клиентов.

Список закрыт `.gitignore`, но `.gitignore` — не замена вниманию перед коммитом.
